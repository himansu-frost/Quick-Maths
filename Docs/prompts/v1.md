==================================================
1. PRODUCT VISION
==================================================

Product name: Quick Maths

Tagline: Get better at maths.

Quick Maths is an everyday mathematics learning and
practice platform primarily designed for college students
and Gen Z, with the ability to serve a broader audience.

The application helps users understand and practice
mathematics used in everyday life.

Examples include:

- Budgeting and expense calculations
- Shopping discounts
- Splitting bills
- Cooking and recipe scaling
- Loans, EMI, and interest
- Travel costs and mileage
- Time and schedule calculations
- Fitness and health-related numerical calculations
- Home repair measurements
- Salary and tax estimates
- Ratios and proportions

The goal is not simply to provide answers.

The application should teach users how to calculate
answers independently, understand the underlying
principles, practice repeatedly, and track improvement.

The central learning loop is:

LEARN → PRACTICE → RECEIVE FEEDBACK → IMPROVE → RETURN

11. MATHEMATICAL QUESTION ENGINE
==================================================

This is a critical part of the application.

Implement a deterministic mathematical question engine.

Do not use a language model as the runtime authority
for generating correct answers or validating them.

The system should generate questions from reusable
templates and calculate the expected answers using
tested TypeScript functions.

A question template should support:

- Topic identifier
- Subtopic identifier
- Difficulty
- Parameter ranges
- Question text generation
- Correct-answer calculation
- Accepted answer format
- Rounding rules
- Hint generation
- Explanation generation
- Validation tests

Example:

Template:
A product costs ₹{price} and has a {discount}% discount.
Calculate the final price.

Generated question:
A product costs ₹2,400 and has a 25% discount.
Calculate the final price.

Correct calculation:
Discount = 2,400 × 25 / 100 = ₹600
Final price = 2,400 - 600 = ₹1,800

The generated question, answer, hint, and explanation
must use the same parameter values.

QUESTION GENERATION REQUIREMENTS:

- Use valid parameter ranges.
- Support different difficulty levels.
- Avoid invalid or nonsensical scenarios.
- Avoid excessive repetition within a session.
- Generate questions with unambiguous expected answers.
- Use suitable numerical precision.
- Explain required units.
- Handle money and percentage rounding consistently.
- Validate generated questions using automated tests.

For financial calculations, use appropriate precision.
Do not depend on floating-point equality for currency
comparisons when a decimal or integer-minor-unit
approach is more appropriate.

For EMI, implement the standard EMI formula and
test edge cases, including a zero-interest case.

For discounts, support reverse calculations and
successive discounts when those templates are available.

For mileage, define the expected unit clearly,
such as kilometres per litre.

For ratios, validate the total parts and proportional
distribution.

For time calculations, handle day boundaries correctly.

For every question, ensure the displayed explanation
matches the actual calculation.

A question should not be published if its generated
answer fails validation.

Create unit tests for the mathematical functions
and question templates.
